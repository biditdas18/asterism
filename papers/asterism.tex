\begin{abstract}
Large language model (LLM) assistants increasingly persist user information across sessions as unstructured ``memory'' summaries. Such summaries behave like an unindexed heap: every stored fact carries equal retrieval priority, and nothing signals which facts currently matter most. We present Asterism, a local-first system that builds a weighted, decaying knowledge graph from conversation history and injects a ranked subset into the model's context at inference time. The central design claim is architectural: the graph functions as a priority index over flat memory, in the same sense that a B-tree indexes an ordered file, with node weight acting as a salience signal analogous to an index key. We evaluate across five retrieval conditions, two independently authored personal graphs, 100 priority queries per graph, and five assistant models spanning four vendors, with decoding held fixed and the graph reseeded before every call. First, the deployed system --- a weighted graph injected with a prioritization instruction --- increases \emph{decisiveness under ambiguity} over a flat list of the same facts: scored with a pre-registered, held-out-validated commit/hedge metric, every model commits to a weight-justified answer more often under the graph, in nearly every run. Second, that decisiveness is \emph{more accurate} than flat memory in every model, but absolute accuracy remains low --- the best model identifies the true top priority only about 40\% of the time and most far less --- so the graph delivers a strong relative lift on a problem far from solved. Third, we decompose the effect with two further conditions, the graph with its instruction stripped and a flat list with that instruction added. Decisiveness does not separate them: the instruction alone raises commitment in all ten model--graph cells (mean $+11.2$ points), by as much as the structure alone (mean $+10.7$), so a commit-rate gap is not by itself evidence of a structural effect. Accuracy does separate them. Structure alone improves correctness over a flat list in all nine measured cells, seven separably from zero, against five of ten for the instruction alone, and among committed answers it is more precise than the instruction-only condition in all nine measured cells ($+5.1$ to $+31.4$ points, four separable). The components are complementary rather than redundant: the deployed system's correctness gain matches or exceeds the better single component in all ten cells and strictly exceeds it in nine. A twelve-query pilot had read this decomposition as purely structural; at one hundred queries the supportable reading is that the instruction buys decisiveness while the weighted structure makes that decisiveness accurate. We report the instrument's own reliability (scorer--human agreement $\kappa=0.64$, with errors that bias the measured gap toward the null), and two components an automatically-populated index requires: an entity-resolution layer whose accuracy ceiling we measure, and a supersession mechanism that demotes contradicted facts. Retrieval latency scales approximately linearly, near 34\,ms at 10{,}000 nodes. We release the full system, both benchmark graphs, and all negative results.
\end{abstract}

\section{Introduction}

Conversational LLM systems now routinely retain information about a user between sessions. The dominant form this retention takes is a running natural-language summary: a list of facts, preferences, and history that is prepended to the model's context on later turns. This format is simple and effective for recall, but it is structurally flat. Every fact sits at the same level. There is no representation of which facts are central to the user and which are incidental, no representation of how facts relate, and no representation of which facts have been superseded by newer ones.

In database terms, a flat memory summary is an \emph{unindexed heap}: a store you can scan but cannot query by priority. The contribution of this paper is to take that analogy literally and build the missing index. Asterism constructs a weighted directed graph from a user's conversation history, where nodes are concepts and entities, edges are relations, and edge and node weights encode how frequently and recently the user has engaged with each. At inference time, the highest-weight region of the graph is serialized into the model's context. The weight ordering is the index: it tells the retrieval step which facts to surface first, exactly as an index key tells a query planner where to look before touching the underlying data.

This framing makes a falsifiable prediction. If the graph acts as a priority index and not merely as a memory store, its benefit over an unstructured list of the same facts should appear specifically on tasks requiring prioritization and largely vanish on tasks requiring only recall. We test this directly, designing the test to survive the obvious confounds. The deployed graph condition does two things at once: it imposes a weighted structure \emph{and} instructs the model to prioritize high-weight nodes. A naive graph-versus-flat comparison cannot separate these, so we run five conditions against the same underlying facts, two of which add the instruction without the structure and impose the structure without the instruction (Section~\ref{sec:poc}). We hold decoding fixed, reseed the graph before every call so no response conditions on state a prior response wrote, and repeat the entire design across two independently authored personal graphs, one hundred priority queries per graph, and five assistant models spanning four vendors, five runs each.

We report three findings, each at its actual scope. First, on priority queries the weighted-graph-plus-instruction condition produces more decisive commitment than a flat list of the same facts in every model we test, over two graphs and one hundred queries each, in nearly every run. Second, that decisiveness is \emph{more accurate} than flat memory in every model, but we state absolute levels plainly rather than only the relative lift: even the strongest model is correct only about 40\% of the time and most well below that, so the graph improves priority routing without solving it. Third, we decompose the benefit into the graph \emph{structure} and the prioritization \emph{instruction}, correcting a reading a smaller pilot had encouraged. On decisiveness the two are indistinguishable, so a commit-rate gap cannot attribute the effect to structure; accuracy distinguishes them, with structure alone more often right than instruction alone in every measured cell, and the two act complementarily rather than redundantly. We prefer this decomposition, with its low absolute ceiling and underpowered cells stated openly, to the cleaner-sounding structural claim the full data does not support.

An index over a live, automatically-populated store raises two further engineering problems, which we treat as first-class. Entity resolution: without it the graph fragments into near-duplicate nodes that corrupt the weight signal. Supersession: a fact a later turn contradicts must be demoted, so a stale edge does not compete with the new one for retrieval. Sections~\ref{sec:er} and~\ref{sec:temporal} take up each in turn.

We make four contributions. We frame a weighted personal knowledge graph as a priority index over flat LLM memory, with node weight as the salience key (Section~\ref{sec:framing}). We run a five-condition evaluation over two independently authored graphs, one hundred priority queries each, and five models from four vendors, which separates the deployed system's benefit from the value of memory per se and from the prioritization instruction (Section~\ref{sec:poc}). We measure where embedding-based canonicalization of short concept labels stops working, and report that negative result (Section~\ref{sec:er}). We give a supersession mechanism that demotes contradicted facts from retrieval, with a latency study showing approximately linear scaling to 10{,}000 nodes (Sections~\ref{sec:temporal},~\ref{sec:latency}). All code, benchmarks, and the seeded evaluation graph are publicly available.

\label{sec:system}

\paragraph{Extraction.} Each conversational exchange is processed by a small extraction model that emits (source, relation, target) triples. Sources and targets become nodes; relations become labeled, weighted edges.

\paragraph{Weighting and decay.} Every node and edge carries a scalar weight. Repeated engagement increases weight; disuse decreases it. Following the Hebbian principle that co-activated connections strengthen \citep{hebb1949organization}, an edge is reinforced whenever the model traverses it while answering a query. The complementary process is decay: an edge or node that accumulates session exposure without being traversed loses weight and is eventually pruned. Decay is measured in active session time rather than wall-clock time, so a concept does not fade while the user is simply away. This weight signal, accumulated over many sessions, is what the index ranks on.

\paragraph{Retrieval.} On each turn, the graph is queried for its highest-weight nodes and their relations, which are serialized into a compact block and placed in the model's system context. This is the read path of the index. We deliberately keep it simple: an ordered scan by weight, returning the top-$k$ nodes. Section~\ref{sec:latency} shows this is inexpensive even at ten thousand nodes.

\section{The Graph as a Priority Index}
\label{sec:framing}

The organizing idea of this work is that the structures a database uses to make an unindexed file queryable map onto the problem of making flat LLM memory prioritizable. We make the correspondence explicit because it drives both the design and the evaluation.

A flat memory summary is a heap file: an append-only list of facts with no access structure. You can read all of it, but you cannot ask it ``what are the ten most important facts about this user'' without scanning everything and imposing an ordering after the fact. A B-tree \citep{bayer1972organization} solves the analogous problem for ordered files by maintaining a separate structure whose keys let a reader locate relevant records in logarithmic rather than linear cost. The key is not the data; it is a priority-ordered pointer into the data.

Asterism's weighted graph plays the role of that index over the heap of conversational facts. \textbf{Node weight corresponds to the index key:} weight is the quantity the retrieval step orders on, so a high-weight node is a high-priority pointer, surfaced first just as a B-tree directs a reader to the most relevant page before touching the file. \textbf{Graph traversal corresponds to query planning:} answering a query by walking weighted relations is a plan over the memory space rather than a full scan of the flat summary. \textbf{Decay corresponds to an eviction policy:} pruning low-weight, unused nodes keeps the working index small and current, so retrieval priority reflects present rather than historical relevance. And crucially, \textbf{the underlying facts persist} --- decaying a node removes it from the \emph{index}, not from the record of what was said, mirroring the removal of an index entry without deleting the row.

Graph-structured memory for LLMs is not itself new (Section~\ref{sec:related}). Our claim is narrower: that the \emph{weighting} of such a graph should be understood and evaluated as an index key, and that doing so predicts where the structure helps. The next section tests that prediction.

\section{Core Evaluation: Index Structure versus Flat Recall}
\label{sec:poc}

\subsection{Design}

Evaluating a memory system risks conflating three different benefits: the benefit of having memory at all, the benefit of the particular structure imposed on it, and the benefit of instructing the model to act on that structure. The graph condition as deployed carries all three: it supplies facts, it imposes a weighted structure, and its system prompt instructs the model to prioritize high-weight nodes. To separate them, we run five conditions against the \emph{same underlying facts}:

\begin{enumerate}
  \item \textbf{Graph.} The top-weighted subgraph is injected, preserving weight ordering and relational structure, with an instruction to prioritize high-weight nodes (the deployed condition).
  \item \textbf{Flat list.} Every node label is injected as an unordered, unweighted list: the same facts are present, and only the structure and salience signal are removed.
  \item \textbf{Flat list + instruction.} The same unordered list, with the prioritize-and-commit instruction the graph carries added. This isolates the \emph{instruction}.
  \item \textbf{Graph, neutral.} The same weighted structure, with the explicit prioritize/commit instruction removed. This isolates the \emph{structure}.
  \item \textbf{None.} No memory is injected.
\end{enumerate}

Two contrasts do the work. \textsc{Graph} vs.\ \textsc{Flat list} isolates structure-and-weighting from information content, since both see identical facts. \textsc{Graph, neutral} vs.\ \textsc{Flat list}, together with \textsc{Flat list + instruction} vs.\ \textsc{Flat list}, separates the effect of the structure from the effect of the instruction. The pre-registered rule was: if the effect is instructional, the instruction added to a flat list should reproduce it and the instruction-free graph should lose it; if it is structural, the reverse. That rule presumes the two routes are mutually exclusive. They are not. On decisiveness both antecedents fire, so the dichotomy does not resolve on the commit metric (Section~\ref{sec:poc}). We therefore resolve it on accuracy, which the same five conditions support with no change to the frozen scorer, the query set, or the labels. \textsc{None} is a reference point.

We evaluate on two independently authored personal graphs of roughly fifty nodes each, organized into weighted domain/theme/concept chains. The two describe deliberately different users: one an independent technical researcher, one a freelance designer with caregiving and family obligations. Their domain mixes and priority \emph{shapes} differ, so a replication across both is evidence of generality rather than of one graph's idiosyncrasy. For each graph we focus the quantitative comparison on \emph{priority queries}: one hundred questions that ask what the user should focus on, what matters most, or which of two things to prioritize, each requiring the model to choose or rank rather than merely recall. The queries were generated by filling each graph's node labels into a fixed bank of question templates, and were frozen before any evaluation call; because the generator is templated and not one of the models under test, the query set cannot favor any model. For each query we derive the ground-truth highest-priority node from the seed weights, and flag as near-ties those whose top-two candidates fall within the decay step. Near-ties are excluded from the correctness metric, since ``correct'' is ill-defined for them, but retained for the commit/hedge metric, which does not depend on ground truth.

To keep the comparison clean across a large call budget we fix three things. Decoding temperature is pinned to 1.0 on every backend, so cross-model differences cannot be attributed to sampling settings; we report the mean over five independent runs per cell rather than a single draw, and give run-to-run consistency for every contrast so that sampling variance is visible rather than averaged away. The graph is reseeded from the pristine seed before \emph{every} individual call, so no response conditions on graph state that an earlier call's write-back mutated; an invariant check aborts a call rather than run it if the pre-call seed ever drifts. And we repeat the entire five-condition design across five assistant models spanning four vendors --- \texttt{claude-sonnet-4-6}, \texttt{claude-opus-4-8}, \texttt{gpt-5.5-2026-04-23}, \texttt{deepseek-v4-pro}, and \texttt{kimi-k3} --- with five independent runs each. These five are all token-billed frontier models with no hard daily request caps, which is what makes a one-hundred-query campaign feasible; four further models appeared in earlier pilot runs and were excluded on quota and throughput grounds, disclosed in full in Appendix~\ref{app:repro}. The graph-maintenance extractor is a separate, fixed model held constant across all conditions (a local Llama 3.2 3B served over Ollama, with an optional \texttt{claude-haiku-4-5} path). Concept-label embeddings come from \texttt{BAAI/bge-small-en-v1.5} \citep{xiao2023cpack}, 384 dimensions, also held fixed. The assistant model is therefore the only moving part; because the graph is reseeded before every call, extractor output never enters the evaluated context.

\subsection{Metric}

We score each response with a single binary metric: does it \textsc{commit} to a specific ranked answer, or \textsc{hedge}? A response commits if it names a single top priority or makes an explicit choice and justifies it; it hedges if it defers the decision to the user, enumerates options without selecting, or answers ``it depends.'' The classifier is a deterministic rule, pre-registered and frozen before the evaluation run. We validated it on a held-out set of eleven hand-labeled responses drawn from earlier development runs, not from the evaluation set; it agreed on 11 of 11. We report the frozen classifier's output without post-hoc adjustment. Restricting the metric to priority queries is deliberate: commit-versus-hedge is only meaningful for questions that call for a ranking. Descriptive recall queries, for which a flat list is sufficient by construction, do not admit this metric and are excluded from it.

Because the entire dependent variable rests on this classifier, we also validate it against human judgment on the evaluation data itself, not only the development set. One author independently labeled all 36 responses of one full run (twelve queries across the three core conditions) as commit or hedge without seeing the classifier's labels: raw agreement was 83\% and Cohen's $\kappa$ was 0.64 (substantial). All six disagreements run in the direction that understates the graph condition relative to the flat list, so the measured graph$-$flat gap is a conservative estimate of the true difference; we did not retune the classifier after seeing them. Appendix~\ref{app:repro} gives the breakdown, and the scorer--human comparison sheet is released with the code.

Table~\ref{tab:commit} reports the result across five models, two graphs, and one hundred queries per graph. We read it in three passes.

\paragraph{Finding 1: the deployed system increases decisiveness in every model.} Compare the \textsc{Graph} column (the weighted graph plus prioritization instruction, as deployed) to \textsc{Flat list} (the same facts, unweighted). The graph$-$flat gap (column G$-$F) is positive for all five models on both graphs, from $+2.6$ (Kimi G1) to $+38.8$ (Sonnet G2), and run-consistent (\textsc{Graph} $>$ \textsc{Flat list} in all five runs for most model--graph pairs, the weakest case being Kimi graph 1 at 3/5, the one cell whose interval spans zero). \textsc{None} commits least throughout. Even GPT shows clear positive gaps here ($+15.2$, $+18.4$), though at pilot scale it had committed at a high baseline that masked any structural benefit. With a larger and harder query set, its no-memory rate is no longer a ceiling. The decisiveness benefit is not confined to models that hedge by default; it appears across the panel.

\paragraph{Finding 2: the decisiveness is more accurate than flat memory, but absolute accuracy is low.} A metric rewarding commitment could reward confident error. Because each seed graph has known weights, the correct top-priority item is defined. We score correctness only on queries whose ground-truth weight separation exceeds the decay step, excluding near-ties, for which ``correct'' is not well defined. That leaves 96 of 100 scorable queries on graph 1 and 69 of 100 on graph 2, which has many near-ties by construction. We lead with the absolute numbers rather than the relative lift. Among scorable queries, the graph condition identifies the actually-highest-priority item in the following fractions: Sonnet 23\%/30\%, Opus 31\%/21\%, GPT 38\%/42\%, DeepSeek 9\%/10\%, Kimi 12\%/11\% (graph 1 / graph 2). So even the strongest model is correct on roughly four in ten priority queries, and most models on one to three in ten. Absolute priority routing is a hard, unsolved problem, and the weighted graph does not solve it. What it does is improve it: in every model and graph the graph condition is more often correct than the flat list (e.g.\ Sonnet 23\% vs.\ 8\%, Opus 31\% vs.\ 8\%, GPT 38\% vs.\ 18\%), so the added commitment is disproportionately correct commitment rather than confident noise. The finding is a real relative gain on top of a low absolute base, and we state both. The correctness gaps for all three contrasts, with intervals, two-sided $p$ values, and run consistency, are the right-hand block of Table~\ref{tab:commit} and Appendix~\ref{app:followup}; absolute correctness and precision for every condition are in Table~\ref{tab:correct}.

\paragraph{Finding 3: decisiveness does not separate structure from instruction; accuracy does, and the two are complementary.} Findings 1--2 concern the deployed system, which couples structure with instruction. The design isolates each: \textsc{Gr,neut} is the weighted structure with the instruction stripped, \textsc{Fl+in} the instruction without the structure. On decisiveness both work, by indistinguishable amounts. The instruction-only gap (Fi$-$F) is positive in all ten cells (mean $+11.2$ points, range $+3.4$ to $+25.2$) and separable from zero in eight. The structure-only gap (Gn$-$F) is positive in eight of nine measured cells (mean $+10.7$) and separable in six (Table~\ref{tab:ci}, Figure~\ref{fig:forest}). A twelve-query pilot had shown the structure-only route separating cleanly, and we read that as evidence the benefit was structural. At one hundred queries the reading does not survive: a bare instruction to prioritize and commit, carrying no weights and no structure, buys about as much decisiveness as the weighted graph does. A commit-rate gap cannot attribute the effect to structure, and we retract that stronger claim.

Accuracy separates them. Against the flat list, the structure-only condition improves correctness in all nine measured cells, separably from zero in seven. The instruction alone improves it in nine of ten cells but separably in only five, and it is flat in exactly the two cells where it moved decisiveness most (Sonnet G1 $-0.2$, GPT G1 $+0.4$). The sharper contrast is precision among committed answers --- of the answers a model does commit to, what fraction are right. The structure-only condition is more precise than the instruction-only condition in all nine measured cells, by $+5.1$ to $+31.4$ points. That direction is unanimous, but only four of nine intervals exclude zero and run consistency is mixed (5/5 runs in three cells, 2/5 in one). We therefore report the sign pattern rather than per-cell effect sizes. Because cells share query sets across models, we attach no pooled significance statistic to the unanimity.

The components are complementary, not redundant. The deployed system's correctness gain matches or exceeds the better of its two single-component gains in all ten cells and strictly exceeds it in nine, and it is the only condition whose correctness gain excludes zero in nine of ten cells. The instruction gets a model to answer; the weighted structure is what makes the answer right; coupling them is worth more than either alone. Kimi graph 1, the weakest cell in the panel, is where nothing separates from zero on either metric, and DeepSeek's graph-1 structure-only cell is missing to the empty-response failure discussed below.

Qualitatively, no-memory responses hedge honestly (``I don't have your priorities''), while flat-list responses, holding the same facts, hedge through filler and reflect the question back to the user; the graph's contribution is the salience signal that lets a model resolve the question rather than perform helpfulness around it.

We record one model-specific failure, because the guard against it is part of the method. DeepSeek, in graph\_neutral on graph 1, repeatedly returned responses reporting normal completion yet containing no text while still consuming output tokens. A universal guard that refuses to score empty or truncated content caught every instance and aborted the affected cell rather than recording a spurious hedge, so we report that cell as missing; it caught an analogous failure in another model during development (Appendix~\ref{app:followup}). Detecting and excluding such outputs, rather than silently scoring them as hedges, is a necessary property of automated LLM evaluation.

\section{Entity Resolution and Its Ceiling}
\label{sec:er}

An index is only as good as the keys it orders. Because Asterism populates its graph automatically from extracted triples, the same concept arrives under many surface forms across sessions; without canonicalization ``AI memory tools,'' ``AI memory tooling,'' and ``AI Memory Tools'' become three nodes, each accumulating a fraction of the weight the underlying concept deserves. Fragmentation splits the salience signal and can prematurely decay a concept that is, in aggregate, highly active.

\paragraph{Two-stage resolution.} We resolve labels at write time in two stages. A normalized exact/prefix match lowercases and whitespace-collapses labels and merges a new label that matches or forms a prefix of an existing one; this is cheap, precise, and caught every clear duplicate in our live label set. Because it cannot merge meaning-equivalent variants sharing no prefix, a second stage falls through to cosine similarity between label embeddings from a compact local model \citep{xiao2023cpack}, merging above a calibrated threshold. The model runs offline on CPU on the write path only, so retrieval latency is unaffected.

\paragraph{The measured ceiling.} The useful result is not that embedding resolution works but where it stops, measured against the live graph; the pattern held across every embedding model tested. Reworded or reordered labels reusing the same vocabulary score 0.92--0.98 and merge correctly (``CLI Tools''/``CLI tool'' 0.982, ``AI Memory Tools''/``AI memory tooling'' 0.969). \emph{True synonym substitution} is where it fails. ``LLM requires GPUs'' against ``Large Language Models need graphics processors'' scores only 0.745, inside the range of merely topically related pairs that must not merge (``Philosophy \& Identity''/``Research Identity'' 0.77--0.88). No single threshold separates the two kinds of pair. We calibrate to 0.92, below which false merges begin, making the resolver conservative: it eliminates rewording-driven fragmentation, the common case, while declining synonym pairs it cannot distinguish from distinct ones. Closing that gap needs supervision, either a fine-tuned equivalence model or an LLM semantic check, which we leave to future work.

\section{Supersession: Demoting Contradicted Facts}
\label{sec:temporal}

An index over a live store must handle facts that change. When a user who ``uses Postgres'' switches to SQLite, naive decay eventually fades the old edge, but until it does both facts coexist and both can be retrieved as current. We add an explicit supersession mechanism scoped to the narrow, detectable case: a new edge from the same source, with the same relation, to a different target. On such a conflict the prior edge is marked superseded via a nullable self-reference and its time-to-live dropped so it becomes eligible for pruning; superseded edges are excluded from default injection, so the model sees only the current fact. A node is withheld only when \emph{every} fact-edge to it is superseded, so a concept with any live relation still appears. Superseded edges are not deleted --- they remain recoverable for explicit history queries (``what did I used to use''), preserving a distinction the flat summary cannot represent: a fact that is outdated versus one that was never true. The rule is deliberately conservative, avoiding open-ended contradiction detection that would risk demoting facts that only appear to conflict.

\section{Latency and Scaling}
\label{sec:latency}

For the graph to serve as an index without harming interactive use, the read path must stay cheap as the graph grows. We benchmarked the retrieval step (loading and weight-ordering nodes and edges for injection, excluding any model call) at three graph sizes over 20 runs each. Mean latency was 0.34\,ms at 102 nodes, 2.81\,ms at 1{,}006, and 33.87\,ms at 10{,}051 (P95 38.7\,ms). A $99\times$ node increase yields a $100\times$ latency increase, so retrieval scales approximately linearly. It stays under 34\,ms at ten thousand nodes, negligible beside the model call it precedes. The linear rather than sub-linear factor is a full-table weight ordering, reducible with a secondary index on the weight column. The supersession filter adds 12--18\% to read latency (30.1 to 35.2\,ms at 10{,}051 nodes), a small cost of correctness within the interactive budget.

\section{Related Work}
\label{sec:related}

\paragraph{LLM memory systems.} MemGPT frames context management as a virtual memory hierarchy, paging information between a limited context window and external storage under LLM control \citep{packer2023memgpt}. Mem0 provides a memory architecture that extracts and consolidates salient facts from conversation, including a graph-structured variant \citep{chhikara2025mem0}. Asterism shares the goal of persistent conversational memory but differs in emphasis: rather than optimizing recall or context-window management, it treats \emph{prioritization} as the core function and evaluates the weighted graph specifically as an index that supplies salience. Our five-condition comparison separates that prioritization benefit from the recall benefit those systems primarily target, and separates the structure from the instruction to use it.

\paragraph{Importance-scored and graph-structured memory.} The nearest prior art to a salience-weighted memory is the memory stream of generative agents, which retrieves observations by a weighted sum of recency, relevance, and an LLM-assigned importance score \citep{park2023generative}; A-MEM similarly builds an evolving, interlinked note structure over agent memories \citep{xu2025amem}. Asterism differs in what the weight is and what is claimed for it. Weight accrues from repeated mention, decays on disuse, and attaches to graph nodes rather than episodes. We evaluate it as an \emph{index key}: we test whether ordering the injected context by weight changes the assistant's answer, not whether an importance score improves retrieval recall. Structurally, GraphRAG builds entity graphs and community summaries for global queries \citep{edge2024local}, HippoRAG applies personalized PageRank over a knowledge graph for multi-hop retrieval \citep{gutierrez2024hipporag}, and Zep maintains a temporal knowledge graph with explicit fact invalidation \citep{rasmussen2025zep}, close in spirit to our supersession step (Section~\ref{sec:temporal}). Those systems optimize retrieval over a corpus or episode store. Our unit is a small personal graph, and our dependent variable is whether the assistant commits to a priority at all. Our contribution is the controlled decomposition of that effect into structural and instructional components.

\paragraph{Retrieval-augmented generation.} RAG retrieves passages by similarity to a query \citep{lewis2020retrieval}: it answers ``what is relevant to this query,'' whereas Asterism's weighting answers ``what is persistently important to this user,'' accumulated across sessions rather than computed per query. We take the empirical comparison between the two as the forward direction (Section~\ref{sec:conclusion}).

\paragraph{Indexing and biological memory.} The B-tree \citep{bayer1972organization} is the canonical priority-ordered access structure over a file too large to scan; we borrow its framing directly as a design and evaluation lever. The weighting dynamics draw on Hebbian plasticity, in which co-active connections strengthen \citep{hebb1949organization,shatz1992developing}, used as motivation for the traversal-strengthening rule, not a claim of biological fidelity.

\section{Conclusion}\label{sec:conclusion}

We presented Asterism, a local-first system that builds a weighted, decaying knowledge graph from conversation history and uses it as a priority index over flat LLM memory. Across five conditions, two authored graphs, one hundred queries per graph, and five models from four vendors, the deployed system is more decisive than a flat list of the same facts in every model, and more accurate in every model. Absolute priority-routing accuracy nonetheless stays low, 42\% at best and often far less, so the graph improves a hard problem without solving it. Decomposing that benefit, decisiveness does not separate the weighted structure from a bare instruction to prioritize: both raise commitment by comparable amounts, and we retract the stronger structural claim a twelve-query pilot had supported. Accuracy does separate them: the structure is more precise among committed answers in all nine measured cells. The components are also complementary, with the deployed pairing matching or exceeding the better single component in all ten cells. We also characterized entity resolution and supersession, showed retrieval scales approximately linearly to ten thousand nodes, and report the low absolute ceiling, the one weak model, and a model-specific empty-response failure our guard excluded.

The comparison these results motivate, which we do not frame as a contest, is against similarity retrieval. Similarity retrieval answers ``what is relevant to this query''; a weighted decaying graph answers ``what is persistently important to this user.'' The graph also adds a traceable, weight-grounded justification for why an item surfaced, and direct user control over what is remembered. Whether that paradigm beats a strong retrieval baseline on prioritization accuracy is worth answering either way, and it is where we take this next.

\section*{Limitations}

Our core metric is a single binary outcome (commit vs.\ hedge), scored over one hundred priority queries per graph, five models, and five runs each. This is a substantial sample, but the queries are templated variations on a fixed bank of prioritization phrasings, so they span the intended task without spanning the full range of ways real users express priority. Two graphs is better than one but is still not a population of users; the two were authored to differ in domain and priority shape, yet both were authored by us, and author-constructed personas may share latent structure a real user distribution would not.

Two limitations of the effect itself deserve emphasis. First, absolute accuracy is low: even the best model identifies the true top priority on only about 40\% of scorable queries, and most models on 10--30\%, so our claim is a relative improvement over flat memory, not a solved priority-routing problem. Second, the structure-only effect is not uniform, and which metric it is measured on matters. On \emph{commit rate} the structure-only gap is separable from zero in only six of the nine measured cells --- the interval includes zero for GPT graph 2 and both Kimi cells, and Kimi graph 1 is outright negative ($-2.6$ points) --- which is part of why we do not rest the structural claim on decisiveness. On \emph{correctness} the structure-only gap is positive in all nine measured cells and separable in seven, the two Kimi cells being the exceptions at $+0.8$ and $+3.8$ points; on precision among committed answers it is positive in all nine measured cells but separable in only four. Kimi is the weakest and least consistent model throughout, and DeepSeek's graph-1 structure-only cell is missing entirely because that model returned recurring empty responses in that condition. So the honest scope is that the correctness effect holds across nearly the whole panel, with one weak model, one missing cell, and several underpowered cells stated openly. Our controls isolate structure from instruction but not the two components \emph{within} the structure: the weighted graph carries both a topology and explicit weight values, and we did not run a condition holding topology fixed while shuffling the weights, so we show structure matters, not whether the weights specifically or the graph shape carry it. Our panel also omits models we attempted but could not complete at this scale --- two Gemini models (daily-quota-limited) and two free-tier open-weight models (throughput and task-comprehension failures) --- which is a disclosed constraint of cross-vendor evaluation on consumer and free tiers.

We also do not compare end-task accuracy against a retrieval baseline such as RAG, or against external memory systems on a shared benchmark; the findings here are characterized behavioral effects on this setup, and the retrieval comparison is the forward direction outlined in the conclusion rather than a result we claim now. The entity-resolution ceiling is a limitation of the current unsupervised approach: true synonym pairs are not reliably merged and can still fragment the index. Supersession is scoped to the same-source/same-relation/different-target case and misses subtler contradictions. Because decay is measured in active-session rather than wall-clock time, decay topology depends on usage frequency: a daily user prunes old interests quickly while a sparse user's graph decays little in real time and can accumulate stale structure over a year. Latency, while linear and small, is measured on synthetic graphs and on retrieval alone; end-to-end latency is dominated by the model call. Finally, the system is single-user and local by design, and we have not studied multi-user or privacy-preserving extensions.

\section*{Ethics Statement}

Asterism is local-first: the graph is stored on the user's own device and no conversational data is transmitted except the user's prompt and the context they choose to inject into their model provider. Deleting the local store removes all derived data. The system infers user priorities from conversation history, and such inferences can be sensitive; because the data and index remain under the user's direct control and can be inspected or deleted, we regard the privacy surface as limited, but any deployment that centralized these graphs would raise concerns that the present design specifically avoids.

\section{Reproducibility Details}
\label{app:repro}

\paragraph{Scorer--human agreement.} Of the six disagreements in the 36-response validation run, the frozen classifier labeled as \textsc{hedge} four graph-condition responses a human read as commitments --- for instance a bare imperative (``Ship the package'') whose form the frozen rule's vocabulary did not cover --- and over-credited two flat-list responses as commitments. Both directions understate the graph$-$flat gap, which is why we report it as a conservative estimate. We did not retune the classifier after seeing these disagreements, since doing so would fit the frozen scorer to the evaluation data it is used to score.

\paragraph{Models excluded from the full-scale campaign.} Earlier pilot runs also included two Gemini models and two free-tier open-weight models. The Gemini models' 250-request daily quota made a hundred-query, five-condition, two-graph campaign infeasible within the evaluation window. The two free-tier open-weight models failed both on throughput and on task comprehension, frequently naming the user node itself as the top priority. We therefore report the five token-billed models at full scale and exclude these four, which is a constraint of evaluating across vendors on consumer and free tiers rather than a property of the models' best available configurations.

The system is implemented in Python over SQLite, with the graph loaded into NetworkX \citep{hagberg2008exploring} for analysis. Triple extraction uses a small instruction-tuned model; entity-resolution embeddings use a compact local sentence-embedding model \citep{xiao2023cpack} producing 384-dimensional vectors, run offline on CPU. The evaluation graph, the five-condition comparison script and its multi-model runner, the latency benchmark, and the entity-resolution and supersession test suites are included in the public repository, together with the frozen scorer, the scorer--human agreement sheet, and all per-run results; reproduction instructions are in the repository README\ifanon{} (anonymized repository: \url{https://anonymous.4open.science/r/asterism-7023/README.md})\else{} (\url{https://anonymous.4open.science/r/asterism-7023})\fi. Latency figures were produced by timing the retrieval function directly with a monotonic clock over 20 runs per scale, on synthetic graphs seeded with weighted domain/theme/concept chains; the real user database is never touched by the benchmark.
