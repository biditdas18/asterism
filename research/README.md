# Research scripts

Standalone evaluation scripts backing the claims in the root [README](../README.md)
and [RESEARCH.md](../RESEARCH.md). None of these are part of the installed
`asterism` package or touch your real `~/.asterism/asterism.db` — each seeds
its own throwaway, isolated SQLite file and deletes it when done.

Run any of them from the repo root (or anywhere — they locate the repo root
themselves):

```bash
python research/poc_compare_v2.py      # the current, corrected eval
python research/poc_compare.py         # superseded first attempt, kept for the audit trail
python research/benchmark_latency.py   # local-only, no API calls
```

| Script | What it measures | Needs API key? |
|---|---|---|
| `poc_compare_v2.py` | Does graph-injected retrieval commit to a specific answer more often than a flat, unweighted list of the same facts (`flat_list`), or no memory at all (`none`)? Corrected scorer, validated against a held-out set *before* the live run. | Yes |
| `poc_compare.py` | The original attempt at the same question. Superseded by v2 (regex bug + a category-mismatched metric on descriptive queries) — kept, not deleted, so the correction is auditable rather than quietly overwritten. | Yes |
| `benchmark_latency.py` | Does graph retrieval latency scale acceptably as the graph grows (100 / 1,000 / 10,000 synthetic nodes)? | No |

## results/

Generated output from the scripts above — full side-by-side responses,
scored commit/hedge tables with per-query labels, and latency numbers.
Regenerated by re-running the corresponding script; not hand-edited.

- `poc_eval_results_v2.md` — **current** quantitative result (start here)
- `poc_results_v2.md` / `.json` — full response text backing it
- `poc_eval_results.md`, `poc_results.md` / `.json` — superseded v1 attempt, kept for the record
- `benchmark_results.md` — latency numbers
